Data pipeline

Reads data.json, regenerated on a schedule by GitHub Actions — identical setup to the Recession Vulnerability Index, so both projects refresh Monday mornings automatically.
01FetchPulls ONS's generator CSV endpoints for retail (JWS3) and hospitality (JWS5) workforce jobs.
02ParseExtracts quarterly period→value pairs for each sector back to 1978.
03ScoreComputes year-on-year and quarter-on-quarter momentum, combines with the latest NLW uprating size.
04PublishCommits an updated data.json; GitHub Pages redeploys automatically.
# .github/workflows/update-lps.yml — same schedule as the RVI project
on:
  schedule:
    - cron: '0 6 * * 1'  # every Monday 06:00 UTC
  workflow_dispatch: {}

jobs:
  refresh:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: python3 fetch_and_score.py
      - run: |
          git config user.name  "lps-bot"
          git config user.email "actions@github.com"
          git add data.json
          git diff --staged --quiet || git commit -m "Auto-refresh LPS data"
          git push

Limitations

  • Correlation, not causation. Sector employment moves for many reasons (consumer demand, weather, seasonal hiring) — a dip after an uprating isn't proof the wage rise caused it.
  • Only two sectors. Care and cleaning are also low-pay-heavy but harder to isolate cleanly in ONS's industry breakdown at this level.
  • NLW history is entered by hand once a year when the new rate is announced — the only part of this pipeline that isn't fully automatic.
  • Weights are judgement-based, not fitted against a formal minimum-wage employment-elasticity model — a natural next step for a dissertation-level version of this.
